# 自定义监控指标使用说明

本文说明如何在当前 `nrec-service-cli` 项目中通过 Micrometer 自定义监控指标，并通过 Spring Boot Actuator 的 `/actuator/prometheus` 暴露给 Prometheus 拉取。

当前项目关键信息：

- Spring Boot 版本：`2.3.12`
- 主模块：`app`
- 启动类：`com.nrec.service.AppApplication`
- 应用名：`spring.application.name=app`
- 测试环境端口：`8080`
- 测试环境 context-path：`/${spring.application.name}`，即 `/app`
- Prometheus 指标地址：`http://127.0.0.1:8080/app/actuator/prometheus`
- 业务 Controller 示例：`com.nrec.service.app.controller.UsersController`
- 业务 Service 示例：`com.nrec.service.app.service.impl.UsersServiceImpl`

## 1. 基础依赖

该依赖已经引入父 POM NRCloud 3.2-SNAPSHOT

```xml
<!--监控模块-->
        <dependency>
            <groupId>com.nrec.base</groupId>
            <artifactId>nrec-prometheus-spring-boot-starter</artifactId>
            <version>${com.nrec.version}</version>
        </dependency>
```

说明：
该依赖中包含如下两个依赖:
- `spring-boot-starter-actuator` 提供 `/actuator/*` 端点。
- `micrometer-registry-prometheus` 负责把 Micrometer 指标转换成 Prometheus 文本格式。

## 2. 暴露 Prometheus 端点

当前 `app/src/main/resources/application-test.yml` 和 `application-pro.yml` 已配置：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: "*"
```

这会暴露所有 actuator web 端点，包括 `prometheus`。如果需要收敛暴露范围，建议改成：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: always
```

验证端点：

```bash
curl http://127.0.0.1:8080/app/actuator/prometheus
```

如果返回中能看到 `jvm_memory_used_bytes`、`http_server_requests_seconds` 等内置指标，说明 Prometheus 输出链路正常。

## 3. 指标命名规范

建议自定义指标统一使用服务前缀，避免多服务指标混在一起时难以识别：

```text
app_users_page_query_total
app_users_create_total
app_users_create_failed_total
app_users_create_duration_seconds
app_users_batch_size
```

命名建议：

- 使用小写字母、数字、下划线。
- Counter 类型指标建议以 `_total` 结尾。
- Timer 在 Prometheus 输出时会展开为 `_seconds_count`、`_seconds_sum`、`_seconds_max` 等序列。
- 不要把用户 ID、订单号、请求流水号等高基数字段放进 tag。
- 推荐 tag 使用低基数字段，例如 `module=users`、`operation=create`、`result=success|fail`。

## 4. 方式一：Counter 计数器

Counter 只增不减，适合统计请求数、成功数、失败数、业务事件次数。

适用场景：

- `/userss/create` 调用次数
- `/userss/delete` 删除次数
- 业务校验失败次数
- 外部接口调用失败次数

示例组件：

```java
package com.nrec.service.app.metrics;

import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

@Component
public class UsersMetrics {

    private final Counter usersCreateTotal;
    private final Counter usersCreateFailedTotal;

    public UsersMetrics(MeterRegistry registry) {
        this.usersCreateTotal = Counter.builder("app_users_create_total")
                .description("Total users create requests")
                .tag("module", "users")
                .tag("operation", "create")
                .register(registry);

        this.usersCreateFailedTotal = Counter.builder("app_users_create_failed_total")
                .description("Total failed users create requests")
                .tag("module", "users")
                .tag("operation", "create")
                .register(registry);
    }

    public void recordCreate() {
        usersCreateTotal.increment();
    }

    public void recordCreateFailed() {
        usersCreateFailedTotal.increment();
    }
}
```

结合当前 `UsersController.addBatchUsers` 使用：

```java
@Autowired
private UsersMetrics usersMetrics;

@ApiOperation(value = "批量添加Users")
@PostMapping(value = "/userss/create")
public Result<Object> addBatchUsers(@RequestBody List<UsersQo> usersQoList) {
    usersMetrics.recordCreate();
    try {
        List<Users> usersList = usersService.copyUsersList(usersQoList);
        return Result.build(usersService.updateBatchById(usersList),
                i18nMessageManager.getMessage(MessageConstant.BATCH_INSERT_USERS) + toJSONString(usersQoList));
    } catch (RuntimeException e) {
        usersMetrics.recordCreateFailed();
        throw e;
    }
}
```

Prometheus 输出示例：

```text
# HELP app_users_create_total Total users create requests
# TYPE app_users_create_total counter
app_users_create_total{module="users",operation="create",} 5.0
```

## 5. 方式二：Timer 统计耗时

Timer 适合统计接口耗时、Service 方法耗时、SQL 组装耗时、外部系统调用耗时。

适用场景：

- `/userss/page` 分页查询耗时
- `UsersServiceImpl.getUsersPageList` 查询耗时
- 批量保存耗时

示例组件：

```java
package com.nrec.service.app.metrics;

import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Timer;
import org.springframework.stereotype.Component;

import java.util.concurrent.TimeUnit;

@Component
public class UsersQueryMetrics {

    private final Timer usersPageQueryTimer;

    public UsersQueryMetrics(MeterRegistry registry) {
        this.usersPageQueryTimer = Timer.builder("app_users_page_query_duration")
                .description("Users page query duration")
                .tag("module", "users")
                .tag("operation", "page")
                .publishPercentileHistogram()
                .register(registry);
    }

    public void recordPageQuery(long millis) {
        usersPageQueryTimer.record(millis, TimeUnit.MILLISECONDS);
    }
}
```

结合当前 `UsersController.getUsersPageList` 使用：

```java
@Autowired
private UsersQueryMetrics usersQueryMetrics;

@ApiOperation(value = "获取Users分页列表")
@PostMapping(value = "/userss/page")
public Result<TablePage<UsersDto>> getUsersPageList(@RequestBody PageBean pageBean) {
    long start = System.currentTimeMillis();
    try {
        Page<UsersDto> page = new Page<>(pageBean.getCurrentPage(), pageBean.getPageSize());
        QueryWrapper<UsersDto> ew = new QueryWrapper<>();
        QueryWrapperUtils.queryWrapperBuilder(ew, pageBean.getTableFilterQoList(), this.getUsersTableFilter().getData(), pageBean);
        usersService.getUsersPageList(page, ew);
        TablePage<UsersDto> tablePage = new TablePage<>(page.getRecords(), page.getTotal());
        return Result.buildSuccess(tablePage, toJSONString(tablePage));
    } finally {
        usersQueryMetrics.recordPageQuery(System.currentTimeMillis() - start);
    }
}
```

Prometheus 输出会类似：

```text
app_users_page_query_duration_seconds_count{module="users",operation="page",} 10.0
app_users_page_query_duration_seconds_sum{module="users",operation="page",} 1.245
app_users_page_query_duration_seconds_max{module="users",operation="page",} 0.238
```

## 6. 方式三：Gauge 当前值指标

Gauge 表示一个可上升也可下降的当前值，适合统计队列长度、缓存大小、在线用户数、当前批处理大小等。

注意：Gauge 需要引用一个长期存在的对象，不能注册局部变量，否则对象被 GC 后指标可能消失。

示例：记录最近一次批量创建用户的条数。

```java
package com.nrec.service.app.metrics;

import io.micrometer.core.instrument.Gauge;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

import java.util.concurrent.atomic.AtomicInteger;

@Component
public class UsersBatchGauge {

    private final AtomicInteger lastCreateBatchSize = new AtomicInteger(0);

    public UsersBatchGauge(MeterRegistry registry) {
        Gauge.builder("app_users_last_create_batch_size", lastCreateBatchSize, AtomicInteger::get)
                .description("Last users create batch size")
                .tag("module", "users")
                .register(registry);
    }

    public void setLastCreateBatchSize(int size) {
        lastCreateBatchSize.set(size);
    }
}
```

结合 `addBatchUsers` 使用：

```java
@Autowired
private UsersBatchGauge usersBatchGauge;

@PostMapping(value = "/userss/create")
public Result<Object> addBatchUsers(@RequestBody List<UsersQo> usersQoList) {
    usersBatchGauge.setLastCreateBatchSize(usersQoList == null ? 0 : usersQoList.size());
    List<Users> usersList = usersService.copyUsersList(usersQoList);
    return Result.build(usersService.updateBatchById(usersList),
            i18nMessageManager.getMessage(MessageConstant.BATCH_INSERT_USERS) + toJSONString(usersQoList));
}
```

Prometheus 输出示例：

```text
app_users_last_create_batch_size{module="users",} 20.0
```

## 7. 方式四：DistributionSummary 统计数值分布

DistributionSummary 用于统计非耗时类数值的分布，例如批量接口入参数量、文件大小、消息大小。

示例：统计 `/userss/create` 每次提交的用户数量。

```java
package com.nrec.service.app.metrics;

import io.micrometer.core.instrument.DistributionSummary;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

@Component
public class UsersBatchSummary {

    private final DistributionSummary usersCreateBatchSummary;

    public UsersBatchSummary(MeterRegistry registry) {
        this.usersCreateBatchSummary = DistributionSummary.builder("app_users_create_batch_size")
                .description("Users create batch size distribution")
                .tag("module", "users")
                .tag("operation", "create")
                .publishPercentileHistogram()
                .register(registry);
    }

    public void recordCreateBatchSize(int size) {
        usersCreateBatchSummary.record(size);
    }
}
```

使用：

```java
usersBatchSummary.recordCreateBatchSize(usersQoList == null ? 0 : usersQoList.size());
```

Prometheus 输出会包含 count、sum、max 等序列。

## 8. 方式五：使用 `@Timed` 注解

如果只想快速统计某个方法耗时，可以使用 `@Timed`。

Controller 示例：

```java
import io.micrometer.core.annotation.Timed;

@Timed(value = "app_users_get_by_id_duration", description = "Get users by id duration")
@GetMapping(value = "/users/{id}")
public Result<UsersDto> getUsersById(@PathVariable(name = "id") String id) {
    // 原有业务逻辑
}
```

Service 示例：

```java
import io.micrometer.core.annotation.Timed;

@Timed(value = "app_users_service_page_query_duration", description = "Users service page query duration")
@Override
public void getUsersPageList(Page<UsersDto> page, QueryWrapper<UsersDto> ew) {
    baseMapper.getUsersPageList(page, ew);
}
```

如果 `@Timed` 加在普通 Spring Bean 方法上没有生效，需要显式声明 `TimedAspect`：

```java
package com.nrec.service.common.config;

import io.micrometer.core.aop.TimedAspect;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MetricsConfig {

    @Bean
    public TimedAspect timedAspect(MeterRegistry meterRegistry) {
        return new TimedAspect(meterRegistry);
    }
}
```

说明：

- `@Timed` 适合简单耗时统计。
- 对于需要记录成功、失败、批量大小等业务语义的场景，建议使用 `MeterRegistry` 显式注册。

## 9. 方式六：AOP 统一统计 Controller 指标

如果希望统一统计所有 Controller 方法，可以写一个切面。当前项目已经使用 Spring AOP，可以新增类似：

```java
package com.nrec.service.common.aop;

import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Timer;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.reflect.MethodSignature;
import org.springframework.stereotype.Component;

import java.util.concurrent.TimeUnit;

@Aspect
@Component
public class ControllerMetricsAspect {

    private final MeterRegistry meterRegistry;

    public ControllerMetricsAspect(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }

    @Around("within(@org.springframework.web.bind.annotation.RestController *)")
    public Object recordControllerMetrics(ProceedingJoinPoint point) throws Throwable {
        MethodSignature signature = (MethodSignature) point.getSignature();
        String className = signature.getDeclaringType().getSimpleName();
        String methodName = signature.getMethod().getName();
        long start = System.nanoTime();
        String result = "success";

        try {
            return point.proceed();
        } catch (Throwable e) {
            result = "fail";
            throw e;
        } finally {
            Timer.builder("app_controller_method_duration")
                    .description("Controller method duration")
                    .tag("class", className)
                    .tag("method", methodName)
                    .tag("result", result)
                    .register(meterRegistry)
                    .record(System.nanoTime() - start, TimeUnit.NANOSECONDS);
        }
    }
}
```

优点：

- 不需要在每个 Controller 方法里手写计时逻辑。
- 可以统一记录 `class`、`method`、`result`。

注意：

- `class` 和 `method` 的组合数量通常可控，可以作为 tag。
- 不要把请求参数、用户 ID、数据库主键作为 tag。
- AOP 适合通用技术指标，业务指标仍建议显式注册。

## 10. 添加全局 tag

可以为所有指标增加统一 tag，例如服务名、环境。

```java
package com.nrec.service.common.config;

import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.actuate.autoconfigure.metrics.MeterRegistryCustomizer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MetricsCommonTagsConfig {

    @Bean
    public MeterRegistryCustomizer<MeterRegistry> metricsCommonTags(
            @Value("${spring.application.name}") String applicationName) {
        return registry -> registry.config().commonTags("application", applicationName);
    }
}
```

输出示例：

```text
app_users_create_total{application="app",module="users",operation="create",} 5.0
```

## 12. 常见问题

### 12.1 访问 `/actuator/prometheus` 返回 404

检查点：

- URL 是否带了 context-path：当前项目应访问 `/app/actuator/prometheus`。
- 是否引入 `spring-boot-starter-actuator`。
- 是否引入 `micrometer-registry-prometheus`。
- `management.endpoints.web.exposure.include` 是否包含 `prometheus`。

### 12.2 `/actuator/prometheus` 有内置指标，但没有自定义指标

检查点：

- 自定义指标类是否被 Spring 扫描到。建议放在 `com.nrec.service.app.metrics` 或 `com.nrec.service.common.config` 下。
- 业务代码是否实际调用了 `record`、`increment` 等方法。
- `@Timed` 是否需要补充 `TimedAspect`。

### 12.3 指标数量暴涨

通常是 tag 使用不当导致，例如：

```java
.tag("userId", userId)
.tag("requestId", requestId)
.tag("id", id)
```

这些 tag 会造成高基数问题，应避免。推荐只使用有限枚举值：

```java
.tag("module", "users")
.tag("operation", "create")
.tag("result", "success")
```

### 12.4 Counter 为什么不能减少

Counter 表示累计事件次数，只能增加。如果需要记录当前值，例如在线人数、队列长度、缓存大小，应使用 Gauge。

## 13. 推荐落地方式

对当前 `UsersController`，推荐按以下层次落地：

1. 使用 AOP 统一统计所有 Controller 方法耗时和成功/失败结果。
2. 对 `/userss/create`、`/userss/delete` 等关键业务操作使用 Counter 统计调用次数和失败次数。
3. 对 `/userss/page` 使用 Timer 统计分页查询耗时。
4. 对批量接口使用 DistributionSummary 统计每次批量数据量。
5. 用 `MeterRegistryCustomizer` 增加 `application=app` 这类全局 tag。

这样可以同时覆盖技术视角和业务视角：

- 技术视角：接口耗时、异常比例、JVM、线程、HTTP 请求。
- 业务视角：用户创建次数、删除次数、批量大小、分页查询耗时。
